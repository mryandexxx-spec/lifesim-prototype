# Scripted game playtest

Run the manual **GQ scripted game playtest** workflow on the desired exact commit/branch; or serve a clean checkout at localhost:8765 with PlayCanvas vendor prepared, install the same Playwright version as existing CI, then run `node tests/gq-playtest-browser.mjs`. No game code, user data, save version or new runtime dependency is involved.

The initial matrix uses fresh browser storage for onboarding, deterministic synthetic household fixtures for queue/cancellation/save and work return, Chromium and WebKit, 390×844 and 320×568. Touch commands use Playwright tap, not DOM click or direct state mutation. Seeded fixtures are explicitly distinguished from fresh play. Per-step screenshot, touch count, targets, elapsed time, observed assertions/failure and exact checkout SHA are in the artifact. Scripted elapsed time includes automation and screenshot overhead; not human UX latency. The PNG header/hash checks do not judge visual quality. The runner records separate open ART/GAME/DEVICE outcomes; inspect the screenshots and reproduce defects before judgement. The existing life integration suite provides independent 7/30-game-day headless checks, not real player sessions.

To extend the suite add a named scenario in tests/gq-playtest/scenarios.mjs with a goal, optional canonical isolated fixture and named steps. Use actual touch input, read-only observations, and explicit resulting state checks. Do not force clicks, inject action commands, use real saves, bypass failures, or claim fun. Longer exploratory sessions, manual visual review, social/creative/career strategy and device acceptance are not covered by this first scripted matrix. Report unmet cases as OPEN, not passed.

## Extended baseline audit
Additional cases cover portrait single/double touch and actual camera pose, both directions of 3D social discovery and queue admission, creative easel admission, career vacancy discovery without commitment and one five-minute unattended Chromium run with sampled game-clock/needs/queue/wallet state. Seeded furniture is explicitly not a purchase-flow test. Scene picking failure is recorded without DOM bypass. No claim of creative completion, long human play, balance/interest, actual touch ergonomics or physical iPhone. 30/120-minute exploratory sessions and comparative multi-day strategies remain separate open work. Evidence is diagnostic, not a release acceptance score.

R3 diagnostic records real input event targets/timestamps and camera displacement samples (up to six seconds); the accepted recognition interval remains 350ms. A single world tap opening a category instead of the resident context remains a failed UX case. Purchased easel discovery records label visibility and then exercises the actual 3D ray-pick path; no command injection. R2 results retained separately; a red audit is not a reason to change gameplay or hide observed defects.
